## Why

当前项目的生产部署仍停留在“拉取代码后直接构建并启动”的层面，没有明确的发布版本、发布记录、数据库快照和快速回滚入口。一旦新版本发布失败，或者代码与数据库状态不匹配，只能靠手工排查和临时导入 SQL，恢复成本高且容易误操作。

本变更将为现有 Docker 部署补齐一套可追踪、可验证、可回滚的发布机制，让每次上线都有版本号、数据库备份和明确的回退路径，降低生产发布风险。

## What Changes

- 引入版本化发布流程，为每次发布生成唯一版本号并记录对应的构建信息与时间。
- 为发布脚本增加发布前数据库备份、发布后健康检查、发布记录持久化能力。
- 提供一键回滚脚本，可回滚到上一个或指定版本，并在需要时恢复对应数据库备份。
- 调整现有 PowerShell 部署脚本职责，统一以 PowerShell 作为生产运维入口。
- 更新 Docker 发布文档，明确版本化发布、数据库备份和回滚的标准操作。

## Capabilities

### New Capabilities
- `release-management`: 管理版本化发布、数据库备份、健康检查、发布记录和快速回滚。

### Modified Capabilities
- (none)

## Impact

- 脚本：重构 `deploy.ps1`，新增回滚与发布记录相关脚本或目录。
- 运维目录：新增发布清单、数据库备份和发布元数据存储位置。
- Docker 运行方式：发布时需要明确镜像标签、版本目录或可回退的 Compose 配置来源。
- 文档：更新 `DOCKER.md` 中的发布、备份、回滚说明与命令示例。
